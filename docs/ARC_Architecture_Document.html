Architecture principle: AI reasoning, orchestration and explanation sit above governed tools. Money, dates, eligibility, authorization and persistence are always deterministic — rules engine, metric contracts, SQL/graph queries, and human gates. The LLM never computes legal amounts, statutory dates, or eligibility verdicts.

1. Architecture Overview

ARC is a layered, durable, human-gated agentic workflow system for PaintCo receivables recovery. It implements two Microsoft Agent Framework (MAF) workflows sharing upstream reconciliation (A1), eight specialised executors (A1–A8), a versioned rules engine (R1–R6), governed tools, and four mandatory human approval gates.

Not eight unrestricted autonomous agents. Each executor has a bounded contract. A1, rules evaluation, clock computation, and A5 self-verification are deterministic. LLM is used for explanation, summarisation, bounded planning, and voice parsing — never for money, dates, or eligibility verdicts.

Cheque selection (deterministic): Newest bounced cheque with return memo; else newest on file. Never delegated to the model.

11. Rules Engine Architecture

Separate versioned component in ARC.Domain/Rules. AI agents invoke rules; they never replace them.

RuleDescriptionOwner
R1aHold if unreconciledFinance / Rules Engine
R1bHold if unapplied_credits / claim_amount > 0.40 (configurable)Finance
R1cHold if Dispute UNDER_REVIEW or active PTP within graceFinance
R2s138_eligible: enforceable debt + valid presentation + qualifying return codeLegal
R3Statutory clock; alerts T-10, T-5, T-2 to named ownerLegal
R4Segregation of duties — recommender ≠ approverArchitecture
R5Block all action under insolvency moratoriumFinance / Legal
R6No notice amount without lineage to source rowsFinance

Rules: versioned config (JSON), independently unit-testable, fail-closed (throw if prerequisite missing), changeable without prompt edits.
